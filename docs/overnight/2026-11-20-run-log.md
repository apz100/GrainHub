### Incident during the smoke run — root cause found (genuine code bug)

Checks 1–6 passed. Then `/api/basis/tracker` returned an empty body
and every later check got Render **502** pages; `/health/live` was
also 502 — the instance was dead. It recovered on its own after a
few minutes (3 × 200 in <1 s). A second run reproduced the pattern
exactly: SLA/summary/facets/preview all 200, then basis tracker →
502 and the instance down again. A third, isolated test on a healthy
instance confirmed it: **one `GET /api/basis/tracker` → 502 after
16.4 s, instance dead afterwards.** 3/3 reproductions. No deploy,
merge, or config change by this run caused it — production runs
master `ee3c3d0`; the bug shipped with the original deploy and §5
item 7 had simply never been exercised until tonight.

**Root cause** (in `_load_price_pairs`, `app/api/routes/basis.py`,
shared by `/tracker` and `/history`):

1. The query loaded **every stored (price, snapshot) pair for the
   org, unbounded**, including each snapshot's `raw_payload_json`
   (a whole day file per snapshot) — the classic way to OOM a
   512 MB free instance.
2. Worse: the row filter `isinstance(item, tuple)` is **False for
   real SQLAlchemy Rows**, so the loader silently discarded every
   row from a real database. The endpoint only ever "worked"
   against the fake sessions in its tests, which return plain
   tuples. Proven locally: a real SQLite session returns 3 pairs
   via a manual join and 0 via the loader. The expensive query ran
   in full (bug 1) and then threw its results away (bug 2).

**Fix (this branch, commit `3f93785`):** unpack rows by index
(works for Rows, tuples, and the fake sessions); defer
`raw_payload_json` (nothing in the basis paths reads it; it still
lazy-loads if ever accessed); cap the load at the newest 100,000
pairs with a `data_quality` note when the cap binds. Two new
regression tests run the loader against a **real** session — the
old tests could not see bug 2 by construction. All 59 basis tests
pass. **Prod verification still required after merge:** call
`/api/basis/tracker` once and expect 200 with ranked rows.
