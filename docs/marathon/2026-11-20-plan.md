# Marathon plan — 8-hour autonomous run, Thu 2026-11-19 23:30 → Fri 2026-11-20 ~07:30 EST

Written for Adam's spec: work that needs **no help, no feedback, and no
decisions from him** while it runs. Anything that would need him is
excluded by design (see "Deliberately excluded" at the end).

## Setup

- **Branch:** `marathon/2026-11-20`, stacked on `overnight/2026-11-20`
  (which is itself unmerged). Stacking is deliberate: Phase C needs the
  FAS world-data fetcher that only exists on the overnight branch.
  Morning merge decision is then one stacked branch, flagged in the
  report. Master and production are never touched.
- **Guardrails (unchanged):** $0 spend · no merges · no vendor contact ·
  LLM and Barchart/DTN stay parked · North Gower = one ordinary source,
  nothing featured · no secrets in git · no writes to the production
  database (all data work is local fixtures/snapshots or read-only API
  reads) · no Chromium-dependent work (sandbox browser cannot egress;
  HTTP-level checks only, which are proven to work).
- **Rhythm:** commit at least hourly; keep a running log in
  `docs/marathon/2026-11-20-run-log.md`; full test gate at every phase
  boundary (API suite + web build must stay green — baseline on the
  stacked branch: 731 passed / 5 skipped). If a phase blocks for more
  than ~45 minutes, document the blocker honestly and move to the next
  phase. Never stall the run on one item.

## Phase 0 — Baseline and work queue (30 min)

Re-verify the stacked branch baseline (API suite, web build), inventory
every API route and every registered collector into the run log as the
night's work queue, and snapshot the live production API's public
responses (read-only) as reference fixtures for later phases.

## Phase A — Endpoint robustness audit (1.5 h)

The basis-tracker bug (unbounded load + row-type assumption that only
worked on fake data) is a *pattern*, not a one-off. Audit **every** API
route for the same class: unbounded queries, raw-payload loading,
pagination gaps, row/ORM assumptions that tests with fakes can't catch.
Write real-database regression tests for each list/report endpoint
(market search, preview, facets, source health, alerts, watchlists,
saved searches, quotes, signals, newsletter, research), fix what the
audit proves broken, and leave a short audit table in the run log:
endpoint × checked × finding × fix-or-clean.

## Phase B — Commodity and location normalization (1.5 h)

Live facets are messy: "Corn", "#2 Yellow Corn", "GLG Cash",
"HARD RED WINTER", "HRS Old Crop Wheat" and more are the same
commodities under different names, which fragments search and the
basis tracker. Build a canonical commodity mapping layer (mapping
table + resolver service, migration on the branch), normalize location
names the same way, and make facets/search group by canonical
commodity while keeping the original label visible. Backfill is a
dry-run-only script (no prod writes). Tests for every mapping rule,
including the ambiguous ones — ambiguous names stay unmapped and are
listed in the report rather than guessed.

## Phase C — Research silo build-out (1.5 h)

Overnight Phase 3 wired the FAS PSD fetcher but no route exposes the
data. Build it out: API routes for PSD world data and NASS series with
DB-backed caching tables (migration on the branch), the decoder wired
end to end, and the web Research pages pointed at the real response
shapes (verified against fixtures built from tonight's live USDA
responses, keys handled only through the connector layer). Verify the
WASDE and Crop Progress file parsers against the current live USDA
files. Result labelled honestly: routes + pages done and tested;
production data flows only after merge + scheduling, which are Adam's
morning decisions.

## Phase D — Collector coverage deepening, HTTP-level (1.5 h)

Re-verify **every** source in `docs/plans/price-source-catalogue.md`
and `docs/plans/collector-coverage.md` by live HTTP fetch tonight;
update both docs with dated statuses. Investigate the Farm Market
News gap properly: the location dropdown lists 336 options but the
default page carries 204 bid tables — work through what the filtered
views and alternate parameters actually return over HTTP and document
exactly which dropdown-only locations (Winchester, Sarnia, Goderich,
Durham, Wellington, Chatham, Kintore, Maxville…) are reachable without
a browser and which are not. Fix or add static adapters where pages
have changed shape, each with fixture tests. No adapter is marked
working without a fixture that proves the parse.

## Phase E — Web resilience for the free tier (1 h)

The live site sits behind an API that sleeps. Give the web app proper
cold-start behaviour: fetch timeouts with retry, skeleton and error
states on the dashboard, sources, and market pages (today a slow API
leaves panels stuck on "Refreshing…"), and a visible "waking the API"
state instead of silent emptiness. Static accessibility pass on the
main pages (labels, contrast, focus order). Web build green at the
end; every changed page listed in the log.

## Phase F — Newsletter and market-report dry run (30 min)

Generate the daily newsletter and weekly market report locally against
realistic seeded data (never prod), check the rendered output line by
line (GrainBids branding, links, dates, no placeholder text), fix what
the dry run exposes, tests included. Delivery stays OFF — this is
generation quality only.

## Final hour — Gates and morning report (1 h)

Full API suite + web build on the branch tip, branch hygiene check
(no secrets, no prod writes, guardrail list re-verified line by line),
and `docs/marathon/2026-11-20-morning-report.md`: per-phase
done / scaffold / blocked with evidence, test counts before/after,
commit list, and the (short) list of things that genuinely need Adam —
each with its cost, $0 unless he chooses otherwise.
